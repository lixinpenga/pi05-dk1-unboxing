# DK1 采集、执行与评测

## 工位和工件

1. 双臂面对面固定在同一刚性台面。纸箱放在左臂一侧，托盘放在右臂一侧，预留共同可达的交接区域。固定左右腕鱼眼相机与顶视相机，安装宽度和俯仰以实际夹爪和工件为准。检查 224×224 的中心裁剪范围，尤其在最远源格位和最远目标槽。
2. 按实际料箱编辑 `configs/scene.yaml`。默认用 5×8 顶层容纳 40 件。行号从靠操作者的物理底部向上数，列号从左向右数。默认首件是源格 `(0,7)` 到目标 `(0,0)`，第 16 件进入目标第 2 行首列。两种相差 180° 的正确触点朝向均合格。替代工件应保留窄槽插入、方向约束和双臂换向三项难点。实测工件宽度、长度和允许倾角后再设定槽间距与裕量。
3. 以五个布置记录场景，四个桌面加一个灯箱。每次重新布置可在各自约 11×11 cm 的范围内独立平移料箱和托盘。用纸质标记记录名义中心和实际位移。标准评测把两者放到名义中心，以灯箱作为评测场景。多样评测的命令可生成随机平移计划，旋转量需现场另记。测试前确认每个偏移都处于双臂可达范围内。

## 驱动和校准

将适配现场设备的 DK1 SDK 源码放到 `external/trlc-dk1`，再执行下列命令。

```bash
# 先安装与 GPU 和本机驱动适配的 PyTorch/torchvision。
uv pip install -e '.[train,robot]'
git -C external/trlc-dk1 checkout 12f5368aefd0381461f2c7ffbb5611b4e8c90de9
# 阻抗模式引用上游源目录中的控制模块和 URDF。
uv pip install -e external/trlc-dk1
cp configs/hardware.example.yaml configs/hardware.local.yaml
```

用稳定的 `/dev/serial/by-id/` 和 `/dev/v4l/by-id/` 路径替换占位符。按 SDK 先独立检查两臂归零、关节单位、左右臂映射、夹爪开闭和物理急停。默认阻抗模式在 DK1 驱动中维护低层位置目标，在本项目控制层运行 50 Hz 的高层循环。可使用 `pos_vel`，此时 `joint_velocity_scaling` 生效，需要另测串口读写是否能满足 20 ms 周期。

`limits` 的四组向量均为 14 维。顺序为左 J1–J6、左夹爪、右 J1–J6、右夹爪。实测并填写可接受的关节上下界、相邻目标变化和目标对当前实测位置的误差。关节值使用 rad，夹爪使用 SDK 的 [0,1]，0 开、1 闭。夹持工件期间夹爪实测值与闭合目标不同，核对该维的跟踪容差。限值超标会停止下发新目标并保存故障。软件限值只检查已知命令边界。驱动可能仍保持最后一个目标，必须配合现场物理急停和限力。连接本身可能使能电机或校准夹爪，程序分别在连接前和每件运动开始前提示确认。初次联调拆除工件、降低速度和力，用单个空载回合检查动作方向。

摄像头按 RGB 640×480 MJPG 配置，默认要求协商到 50 Hz。如果使用 30 Hz 相机可设 `camera_fps: 30`。控制仍以 50 Hz 取各路最近已到达的帧，可能重用相邻视频帧，原始回合保留每路到达时间的相对年龄和帧号。USB 到达时间是软件时间戳；若要毫秒级同步，需使用硬件触发或共享设备时间基准。记录的行时间戳也保留真实控制抖动。导出到训练时按 50 Hz 帧索引组成动作块，动作起始偏移默认为 0。RTC 的在线延迟估计记录在部署日志中。

## Gello 和 VR 示教

Gello 双主臂通过上游 `BiDK1Leader` 输出 14 维关节和夹爪目标。开始前让主臂与从臂对齐，夹爪指令也应一致。VR 使用 WebXR 遥操作适配器，手柄姿态由 MuJoCo 雅可比和差分逆运动学转成关节动作。替换 VR 配置里的 URDF 路径、旋转标定矩阵和双臂参考姿态。VR 模式使用现场提供的兼容适配器，下例假定其源码放在 `external/vr-adapter`。

```bash
uv pip install -e '.[train,robot]'
uv pip install -e 'external/vr-adapter[lerobot,relay]'
uv pip install -e external/trlc-dk1
# 在台式机运行 relay。Quest 安全上下文或远端连接按上游 TLS 指南配置。
vr-teleop-relay
dk1-unboxing record --hardware configs/hardware.local.yaml --teleop vr \
  --scene desk_1 --operator op02 --slot 12 --raw data/raw
```

每段从休息位开始，在一件执行器入槽后回到休息位。建议将左臂正确抬件、右夹爪先闭合再让左夹爪释放、右臂对准并完整入槽作为示教复查点。评级 1 为失败，2 为经明显纠正才继续，3 为轻微失误，4 为基本干净，5 为干净完成。HQ 路线在交接和入槽前放慢并保持速度一致，避免碰槽边。原始回合保留所见图像、实测关节、实际下发的目标、时间与评级。普通导出保留 3–5，HQ 导出保留 HQ 中的 5。裁剪以状态/动作相邻差分与边缘余量实现，可调整参数复查片段。

## 接管与 RTC

```bash
dk1-unboxing plan --rounds 6 --diverse --output outputs/dagger-plan.json
dk1-unboxing rollout --hardware configs/hardware.local.yaml --teleop vr \
  --checkpoint outputs/hq/checkpoints/last/pretrained_model --plan outputs/dagger-plan.json \
  --round 0 --all --rtc baseline --operator op02 --output outputs/dagger-results --raw data/raw
dk1-unboxing export --raw data/raw --output data/dagger --route dagger --repo local/dk1-dagger
```

按 240 回合采集时，第一轮把箱和托盘放中心，将计划中第 0 轮偏移设为零，其余五轮改变位置和角度。按 `i` 由专家接管，`p` 回到策略。接管时使旧队列与在途推理失效，VR 按当前实测关节和最近的夹爪目标重新对齐；Gello 在接管前由操作者对齐主臂。导出将每段人工动作作为独立回合，移除有接管回合中的策略标签，也保留没有接管且完成阶段 5 的完整策略回合。把原 HQ 与接管数据放到同一个 raw 目录再导出。干预切片以 `i/p` 控制权切换为边界。

| 模式 | `reinfer` | `blend` | 使用方式 |
| --- | ---: | ---: | --- |
| `baseline` | 30 | 16 | 默认参数 |
| `fast` | 50 | 20 | 对照高成功率设置 |
| `unguided` | 30 | 0 | 同步时轴仍保持，跳过流匹配去噪时的前缀引导 |

`reinfer` 是旧动作队列还有多少步时可以提交新请求。新块生成期间继续执行旧块。当新块到达时，根据从请求起真实过去的控制周期丢弃新块的前缀。正常延迟约 140 ms 对应七个周期。推理使用上一块未执行动作作为 RTC 引导条件，在归一化坐标内进行，`blend` 表示条件前缀的终点，包含预计已经过去的前缀。日志保存请求队列剩余量、实际延迟步数和每次推理毫秒数，用于计算 P95。过期请求在人工接管后丢弃。队列耗尽即中止本回合。对照同一份权重时保持机械条件、工件及评测计划一致。

## 五阶段评测

| 阶段 | 现场判据 | 键位 |
| --- | --- | --- |
| 1 | 未正确取件，或固定顺序出错 | 默认，顺序错按 `x` |
| 2 | 左夹爪抬起正确工件 | `2` |
| 3 | 工件交给右夹爪，且稳定持有至少 1 秒 | `3` 开始计时，`h` 确认，`c` 清除中断计时 |
| 4 | 正确槽位，两侧均入槽，姿态偏斜或触点朝向错误 | `4` |
| 5 | 正确槽位，正确朝向并完全落座 | `5` |

`s` 标记明显卡死，`q` 或 Ctrl+C 中止。单回合上限 45 秒，连续 10 秒没有更高阶段时停止。先完成前置阶段才能记高阶段，干净插入可同时获得阶段 4 与 5。只有阶段 5 计成功。故障和人工中止单列，保留试验覆盖率。正式实验可对每组做 40 或多轮 40 个试验，并报告分子、分母、95% Wilson 区间和各阶段次数。每次试验结束后人工复位机械臂与场景。如果前一件失败，先以手动和断能规程把它恢复到当前顺序所需的托盘状态，再评测下一件。

`report` 读取消耗同一计划的结果目录。不同 checkpoint 或 RTC 设定用不同结果目录。发生硬件故障后将该次结果保留到该目录外，完成实物复位再复测同一编号。结果记录包括试验计划里对应的料箱/托盘位移与推理时序。本程序的 `--all` 是逐件有人监督的实验模式。
